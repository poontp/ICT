傳統封包過濾 (Packet Filtering)

根據封包的標頭資訊 (Header) 進行檢查，包含來源 IP、目的 IP、來源連接埠、目的連接埠與通訊協定 (TCP/UDP)。

運作層級：OSI Layer 3 (網路層) & Layer 4 (傳輸層)
過濾依據：靜態 ACL 規則 (IP / Port 匹配)
主要局限：無法辨識內容 Payload，也無法紀錄連線狀態
💡 生活比喻： 就像大樓門衛只檢查你的「通行證號碼」與「目的地房間號」，不管你拿的是誰的證件，也不檢查你包包裡裝了什麼。

互動式安全規則庫設定 (ACL Rules Policy)

您可以切換以下規則的開啟/關閉，並即時在上方模擬器體驗過濾效果。

優先順序 服務名稱 通訊協定 (Protocol) 目的連接埠 (Port) 動作 (Action) 規則開關
Rule #1 HTTP 網頁瀏覽 TCP 80 ALLOW (允許)

三大防火牆技術演進與深度對比 (Firewall Generations)

防火牆類型 1. 封包過濾 (Packet Filter) 2. 狀態檢查 (Stateful Inspection) 3. 次世代防火牆 (NGFW / DPI)
OSI 運作分層 Layer 3 (網路層) / Layer 4 (傳輸層) Layer 3 / Layer 4 + 狀態表 (State Table) Layer 3 ~ Layer 7 (應用層全涵蓋)
檢查依據 (Inspection Scope) 僅看 IP、Port、TCP 標記 (SYN/ACK)。 檢查標頭並維護連線狀態表 (SYN, ESTABLISHED)。 深度封包檢測 (DPI)、應用程式識別、內容 Payload、惡意軟體簽章。
防禦外部偽造/反向攻擊 較弱 (無法分辨封包是否為合法的回傳流量) 強 (拒絕任何未經內部發起的外部主動封包) 極強 (結合入侵防禦 IPS、防毒與網址過濾)
效能與處理開銷 (Performance) 極快 (硬體級過濾，延遲低) 快速 (僅需對狀態表進行查找比對) 較耗效能 (需要解包檢測 payload 內容)
典型代表/應用情境 路由器 Access Control List (ACL), iptables 基本規則 傳統企業邊界防火牆、作業系統內建防火牆 Palo Alto, Fortinet, Check Point 等現代企業 NGFW
