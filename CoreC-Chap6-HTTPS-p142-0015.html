1. 三劍客核心概念拆解

簡單來說：HTTP 是講話方式，SSL/TLS 是安全外殼，HTTPS 是兩者結合。

明文傳輸 / 不安全

HTTP

HyperText Transfer Protocol

網頁傳輸的基礎語言。就像明信片，任何人只要在傳輸過程中拿到這張明信片，都能直接閱讀裡面的帳號密碼。

致命缺點
沒有加密，容易被竊聽與惡意篡改。
安全防護協定

SSL / TLS

Secure Sockets Layer / TLS

運作在應用層與傳輸層之間的防彈防盜保險箱。SSL 是舊名，TLS 是新版升級版（現今皆稱 TLS）。

核心功能
身份認證（數位憑證）與數據加密。
安全加密傳輸

HTTPS

HTTP + SSL/TLS (Port 443)

等於裝進加密保險箱裡的 HTTP 信件。資料在網路上發送前先被 TLS 加密，到了目的地才由私鑰解密。

安全保障
防竊聽、防篡改、防假冒（綠色小鎖頭）。

3. SSL/TLS 握手（Handshake）運作原理

HTTPS 在發送網頁前，瀏覽器與伺服器如何安全交換對稱金鑰。

1. Client Hello
瀏覽器招呼與支援演算法
2. Server Hello & Certificate
伺服器回應與 CA 憑證
3. Key Exchange
公鑰加密交換預備金鑰
4. Session Key Ready
生成 AES 對稱金鑰開始加密

步驟 1: Client Hello（客戶端招呼）

瀏覽器發起請求，告訴伺服器：「嗨！我想建立安全的 HTTPS 連線，這是我支援的 TLS 版本和加密演算法選單，還有我隨機產生的一組亂數 Client Random。」
